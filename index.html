Privacy Policy

Health Hub · personal WHOOP integration · Effective 19 October 2026

Health Hub is a personal, self-hosted app that runs on one computer and has one user: the person who built it, Mustafa Tariq. Its WHOOP integration lets that person see their own WHOOP data alongside the rest of their health records. It is not offered to anyone else, and nobody else can create an account or sign in.

What WHOOP data it can access

When the WHOOP account is connected, WHOOP grants the app permission (scopes) to read:

  • Profile: first and last name (read:profile)
  • Body measurements (read:body_measurement)
  • Physiological cycles (read:cycles)
  • Recovery (read:recovery)
  • Sleep (read:sleep)
  • Workouts (read:workout)
  • Offline access (offline), so access can be renewed without signing in to WHOOP again

From these, the app imports into its Health section:

  • Sleep: when each night started and ended; the time asleep; time in bed; minutes awake and in light, deep (slow wave) and REM sleep; sleep performance, efficiency and consistency; respiratory rate; the number of disturbances; WHOOP's sleep need for the night (baseline, sleep debt, recent strain and recent nap); and whether WHOOP is still scoring the night or could not score it. Naps are not imported.
  • Recovery: the recovery score, resting heart rate, heart rate variability (HRV), blood oxygen (SpO2), skin temperature, whether WHOOP is still calibrating to the wearer, and whether the score is still pending
  • Cycles: the day's strain, energy expended (as calories), average and maximum heart rate, the step count when WHOOP provides one, and whether the day's strain is still pending
  • Workouts: the sport, start time, duration, distance, strain, average and maximum heart rate, energy expended (as calories), minutes in each heart-rate zone, and whether WHOOP is still scoring it
  • Body measurement: the weight in the WHOOP profile

When first connected it reads the last year of this data; after that, each sync reads everything since the last successful one (at least the last 14 days, so scores WHOOP finishes later are picked up). The app's server syncs every three hours while it is running, and soon after it starts if a sync is due; it also syncs when Health is opened and the last successful sync was over an hour ago, and when its owner chooses Refresh or Sync now. The imported data is saved straight into Health's data file on the owner's computer. Readings WHOOP has not scored yet are kept as pending, never as zero, and are replaced when WHOOP finishes. The profile name is read only for Test the connection, shown once and not saved. The height in the WHOOP profile is read with the weight but not stored. The app never writes or changes anything in the WHOOP account.

Where it is stored

  • Everything stays on the owner's own computer. The app has no cloud database or hosted server, and by default it only answers requests made on that computer, from its owner's signed-in account.
  • The access token and refresh token WHOOP issues are kept in a private file in the app's data folder on that computer. They are never sent to the web browser or to any other service.
  • Imported WHOOP data is kept with the rest of the owner's health records, in Health Hub's data file on that computer, each record marked as coming from WHOOP. It is included in that data's automatic local backups and in the copy the owner can download from Health settings.
  • A small sync record is kept next to the tokens: when the last sync succeeded, when one last failed and the error message it gave, how far back the WHOOP history has been read, and how many records the last sync added and updated (and whether it was automatic). It holds no health readings. It is deleted on disconnect.
  • The owner's choices for how Health shows WHOOP data (which metric is on the chart, the time range and comparison shown) are saved with the owner's Health settings on that computer.
  • The app's WHOOP client secret is kept in a local configuration file and used only by the app's server.
  • Requests to WHOOP are made directly from that computer to WHOOP's API over HTTPS.
  • After access is approved, WHOOP sends the browser to a small page on this website (callback.html), which immediately passes WHOOP's one-time approval code back to Health Hub on the owner's computer. The page runs only in the browser and stores nothing. Because the code is part of that page's address, this website's host (GitHub Pages) receives it with the page request; the code expires quickly, works only once, and is useless without the app's client secret, which never leaves the owner's computer.
  • The token file is protected by access to the computer itself; it is not separately encrypted. Backup copies the owner makes of the app's data folder may include it.
  • The app keeps no logs of requests or tokens.

How it is used

  • Only to show the owner's own WHOOP data to the owner, inside Health Hub.
  • Not sold, shared, rented or disclosed to anyone.
  • Not used for advertising, analytics, profiling or training any model.
  • No third-party services, trackers or cookies receive WHOOP data.

How long it is kept

An access token is valid for about an hour and is renewed automatically while the account stays connected. Tokens are kept until the WHOOP account is disconnected, or until WHOOP stops accepting them, at which point the app deletes them. Imported records stay in Health until the owner removes them (see below); disconnecting stops new imports.

How to disconnect and delete it

  • In Health Hub, open Health → Settings → WHOOP and choose Disconnect. The app asks WHOOP to revoke its access (WHOOP's revoke endpoint) and deletes the stored tokens and the sync record from the computer.
  • Then choose Remove imported WHOOP data on the same page to delete every record WHOOP brought into Health, leaving what the owner logged by hand. Single records can also be deleted from Health's pages at any time, and a deleted record is not imported again.
  • To remove everything, also delete the app's WHOOP configuration (client ID and secret) and any backup copies of its data folder, including Health's automatic backups made while WHOOP data was present.
  • Data held by WHOOP itself is governed by WHOOP's own privacy policy.

Changes

If the integration changes what it accesses or how it handles data, this page will be updated and its date changed.
